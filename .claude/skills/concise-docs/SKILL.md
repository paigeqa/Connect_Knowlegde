# concise-docs

사람이 읽는 흐름과 에이전트가 파싱하는 구조를 동시에 유지하면서 문서를 압축한다.

## 적용 대상

| 문서 | 성격 |
|---|---|
| `spec.md` | SSOT에 없는 스펙. 표 중심, ID 체계 있음 |
| `qa-guide.md` | 테스트 기준. 목록 중심 |
| `AGENTS.md` | 레포 지도 |
| `testrail/README.md`, 스킬 파일 | 런북·절차 |

**적용하지 않는 것**: `sources/`(원본 아카이브 — 원문 보존), `archive/`(보관용).

## 규칙 (전부 적용)

1. 결론 먼저 — 핵심·의사결정 정보를 첫 1~2줄에.
2. 삭제 먼저 — 군더더기·수식어 제거("기본적으로", "~할 수 있습니다").
3. 능동·단정 — 헷지("아마", "~인 것 같다") 제거. "X를 반환한다" 형식.
4. 구체·사실 — 숫자·버전·정확한 동작. 추상어 금지.
5. 한 문단 한 주장.
6. 계층·목록 우선 — 3줄+ 나열은 표/불릿.
7. 중복 0 — 같은 내용 한 곳만.
8. Why 함께 — 규칙엔 이유를 붙인다.
9. 사실/의견, 결정/가정 구분.
10. 볼드 절제 — 항목당 1개 이하. 볼드는 스캔 도우미로만.

## 쉬운 말로 쓴다

이 레포 문서는 **어려운 말을 쓰지 않는다.**

- 한 문장에 개념 하나
- 추상적으로 압축한 표현보다 구체적인 예시
- 전문용어를 쓸 거면 바로 옆에 풀어 쓴다
- 문단보다 목록·표를 먼저 고려한다

## 적용 우선순위 (안전)

**사실 손실 0이 최우선.** 규칙과 사실 보존이 충돌하면 사실 보존이 이긴다 — "불확실하면 남긴다".

| 위험도 | 규칙 | 방침 |
|---|---|---|
| 저위험 | rule 10 볼드 절제 | 자유 적용. 볼드 마크업은 사실이 아님 |
| 저위험 | rule 2의 명백한 filler | 자유 적용 |
| **고위험** | rule 2·3의 "~할 수 있다" | 보통 실제 capability(사실)다. 함부로 지우지 않는다 |
| **고위험** | rule 7 dedup | 두 곳의 디테일이 다르면 남긴다 |
| **금지** | 전체 산문 재생성 후 통째 덮어쓰기 | ID·숫자·결정이 drift한다 |

## 이 레포에서 특히 지킬 것

- **ID를 지우지 않는다** — `F-*`, `Δ-NN`, `Q-N`, `E-*`, `C1277xx`(TestRail). 케이스·문서 추적의 키다.
- **코드 근거를 지우지 않는다** — `stage-access.ts:94` 같은 파일:줄 표기는 SSOT에서 온 검증 근거다.
- **`확정` / `미결` / `폐기` 상태 표기를 건드리지 않는다.**
- **SSOT 링크를 지우지 않는다** — 겹치는 설명을 SSOT로 넘긴 자리다. 링크를 지우면 정보가 사라진다.
- **폐기 항목의 취소선 원문(`~~...~~`)을 지우지 않는다** — 옛 케이스를 삭제할 때 판단 근거가 된다.

## 안전 절차

1. 적용 전 백업 (또는 커밋된 상태에서 시작).
2. 가능하면 기계적·결정적 변환으로 처리해 검증 가능하게 만든다. 예: 볼드 마크만 제거.
3. 검증 — 변환이 사실을 안 바꿨음을 증명한다.
   예) `**`를 전부 제거한 텍스트가 변환 전후 동일한지 비교.
4. ID·숫자·링크 개수를 변환 전후로 세서 같은지 확인한다.
5. 검증 통과 시에만 덮어쓰기. **줄 수·변경 요약을 보고한다.**
