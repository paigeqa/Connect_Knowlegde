# concise-docs

사람이 읽는 흐름과 에이전트가 파싱하는 구조를 동시에 유지하면서 문서를 압축한다.

## 규칙 (전부 적용)
1. 결론 먼저 — 핵심·의사결정 정보를 첫 1~2줄에.
2. 삭제 먼저 — 군더더기·수식어 제거("기본적으로", "~할 수 있습니다").
3. 능동·단정 — 헷지("아마", "~인 것 같다") 제거. "X를 반환한다" 형식.
4. 구체·사실 — 숫자·버전·정확한 동작. 추상어 금지.
5. 한 문단 한 주장.
6. 계층·목록 우선 — 3줄+ 나열은 표/불릿.
7. 중복 0 — 같은 내용 한 곳만.
8. Why 함께 — 규칙엔 이유를 붙인다.
9. 사실/의견, 결정/가정 구분.
10. 볼드 절제 — 항목당 1개 이하. 볼드는 스캔 도우미로만.

## 문서 타입: 사람용 + 에이전트용 (혼용)
- 사람이 읽는 흐름 유지.
- 에이전트가 파싱할 구조 유지(표, 체크리스트).
- 볼드는 스캔 도우미로만.

## 적용 우선순위 (안전 — 2026-06-10 학습 반영)
사실 손실 0이 최우선. 규칙과 사실 보존이 충돌하면 사실 보존이 이긴다("불확실하면 남긴다").

- 저위험(자유 적용): rule 10 볼드 절제(볼드 마크업은 사실이 아님), rule 2의 명백한 filler.
- 고위험(보수적): rule 2/3에서 "~할 수 있다"는 보통 실제 capability(사실)이니 함부로 지우지 않는다. rule 7 dedup은 두 곳 디테일이 다르면 남긴다.
- 금지: 전체 산문 재생성 후 통째 덮어쓰기(대형 SoT에서 ID·숫자·결정 drift 유발).

## 안전 절차
1. 적용 전 백업.
2. 가능하면 기계적·결정적 변환(예: 볼드 마크 제거)으로 처리해 검증 가능하게 만든다.
3. 검증: 변환이 텍스트(사실)를 안 바꿨음을 증명. 예) `**` 전부 제거한 텍스트가 변환 전후 동일.
4. 검증 통과 시에만 덮어쓰기. 라인 수·변경 요약 보고.
